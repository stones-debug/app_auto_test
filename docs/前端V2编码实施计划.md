# 前端 V2 编码实施计划

> 依据：`docs/前端页面布局与交互V2详细设计说明书.md`（V2.0 权威设计）
> 测试规则：**每个 Step 的所有子任务完成后，才执行该 Step 的完整测试（Step 门禁）**，全部通过后提交一次。

## 实施原则

- 每个 Step 是一个**独立可验证的交付单元**：包含多个子任务，所有子任务实现完成后，一次性运行该 Step 的验收命令。
- Step 中途不做完整测试集 / 不提交；只允许轻量语法自检。
- 验收命令（按涉及范围组合）：
  - 后端：`uv run ruff check app/ tests/ worker.py scripts/` + `uv run pytest tests/ -q` + `uv run alembic check`
  - Agent：`uv run ruff check .` + `uv run pytest tests/ -q`
  - 前端：`npm run test`（vitest）+ `npm run build`（vue-tsc + vite）
- 提交信息：`feat(backend|frontend|agent): Step N <内容>`。

## 阶段 1：后端契约补齐

### Step B1 分页与错误码规范
子任务：
- [ ] `PageResult` 统一补 `page/page_size` 字段（消除前后端类型不一致）。
- [ ] `get_pagination` 支持 `page_size` 20/50/100。
- [ ] 领域错误统一为 `{code, message, field_errors}`，兼容既有字符串 `detail`。
- 门禁：后端 ruff + pytest + alembic check。

### Step B2 项目成员管理补齐
子任务：
- [ ] `GET /projects/{id}/member-candidates?keyword=&limit=`（排除 owner/已有成员，limit<=20）。
- [ ] `PATCH /projects/{id}/members/{user_id}`（改角色；admin 边界：不能改自己、只能管 member/viewer）。
- [ ] `DELETE /projects/{id}/members/{user_id}`（移除成员）。
- [ ] `list_members` 返回 owner 虚拟行（membership_id=null）。
- [ ] 权限矩阵测试：owner/admin/member/viewer 越权 403/409。
- 门禁：后端 ruff + pytest + alembic check。

### Step B3 元素/用例扩展

- [ ] `GET /projects/{id}/element-pages` 分组统计（page_name,count，含"未分组"）。
- [ ] 用例列表项加 `step_count/assertion_count/last_execution_status/last_execution_at`。
- [ ] `/elements/{id}/usage` 加可选 `step_orders`。
- 门禁：后端 ruff + pytest + alembic check。

### Step B4 执行接口扩展
子任务：

- [ ] 测试：分页筛选 total 与 items 一致、扩展字段填充。
