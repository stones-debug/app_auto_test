> 适用：《APP自动化测试平台_详细架构实施方案.md》V1.1（第 10 章优先）。
> 本文记录 2026-08-21 复核后 Step 1～12 修复引入的接口/协议/数据变更，正文与本文冲突以本文为准（正文第 10 章之外）。

## 1. REST API 变更

### 1.1 执行重试 `POST /executions/{id}/retry`

- 请求 body **必填**：`{ device_id: number, timeout_seconds?: number }`，缺失 device_id 返回 400 `DEVICE_REQUIRED`。
- 前端三个入口（执行列表、执行详情、报告详情）统一经 DevicePicker 选定设备后携带 body。
- 服务端复制：`retry_of=原执行 id`、`parameters`、`suite_id/case_id/type` 原样；`timeout_seconds` 缺省沿用原执行。

### 1.2 强制释放设备 `POST /devices/{id}/release`（管理员）

- 返回 `DeviceReleaseResponse`：
  ```json
  { "action": "released | stop_requested | finalization_pending",
    "device": DeviceOut, "execution_id": int|null, "execution_status": str|null }
  ```
- 语义：无锁 → released（按 Agent 在线态 idle/offline）；queued → 原子取消并清锁 → released；
  running → 请求停止（stopping），**保持 busy/locked** → stop_requested；stopping → 幂等 → stop_requested；
  终态未汇总（finalized_at 为空）→ 保持锁 → finalization_pending；终态已汇总 → 清陈旧锁 → released。
- FastAPI 不直接调用 Worker 终态汇总；报告汇总与正常设备释放仍由 Worker 完成。

### 1.3 Agent 注销 `DELETE /agents/{id}`（管理员）

- 从硬删改为**软注销**：置 `agents.deleted_at`，Agent/Device/Execution/Report 行全部保留。
- 存在 queued/running/stopping 执行时返回 409 `AGENT_HAS_ACTIVE_EXECUTIONS`（含执行 ID），不做部分修改。
- 同时：所属 Device 置 offline（陈旧锁记录日志并清空）、删除 AgentUser 绑定与 DevicePreference。
- 软注销 Agent 的访问（deps/列表/上传/WS 注册）一律视为不存在/拒绝。

### 1.4 Agent 绑定重新激活 `POST /agent/bind`

- 软注销实例可重新激活：必须同时提供有效 user key 与**仍匹配的旧 machine PSK**；
  成功后旋转生成新 machine PSK（数据库哈希轮换），清空 deleted_at，更新 hostname/platform/version。
- 无旧 PSK 时返回 409 并提示“联系平台管理员彻底重置”，不允许仅凭 install_id 劫持旧实例。

### 1.5 报告详情 `GET /reports/{id}/detail`（与 `GET /reports/{id}`）

- 新增 `logs_total: int`、`logs_truncated: bool`：报告日志超过 `report_max_logs`（默认 20000）时
  只返回最后 N 条（保持正序），前端与 HTML 报告显示“仅展示最后 N/M 条日志”。
- HTML 缓存带模板/数据版本标记（当前 `logs-truncation-v1`），版本变更后旧缓存自动重生成。

## 2. WebSocket 协议变更

- `start_test` 增加 `protocol_version`（取 `backend/app/protocol/action_registry.json`）。
  Agent 收到不兼容版本时不上报进度，回 `execution_result{status:"error", error_message:"协议版本不兼容…"}`。
- Agent 入站消息（register/heartbeat/device_list/log/step_result/assertion_result/execution_result）
  经 `backend/app/schemas/ws.py` 按 type 校验；非法消息回
  `{type:"error", code:"PROTOCOL_ERROR", message:…}`，不写 DB。
- 正常 step/assertion/execution 消息语义不变。

## 3. 数据库变更

- `agents` 新增 `deleted_at timestamptz` + 索引（迁移 `7f33770e371e`，head）。
- 不删除历史 Device，不修改 `executions.device_id` 外键（保留循环 FK 设计）。
- 终态汇总所有权 CAS：`_mark_terminal` 以 **`finalized_at is null`** 为唯一条件；
  Agent 回传终态只写 status/finished_at；Worker 汇总成功才写 finalized_at。
- Worker-001 新增恢复扫描 `finalize_unfinished_terminal()`（周期与 timeout scan 一致）。

## 4. 前端内部接口

- `DevicePicker` 的 `created` 事件携带 `Execution`；expose 的 `open` 返回 `Promise<Execution | null>`。
- `RunTarget` 增加 `{ kind: 'retry'; executionId }` 分支；三个重试入口共用 `useExecutionRetry`。
- Step 顶层字段 `continue_on_failure: boolean`（必填，不入 params）；click `wait_timeout` 0..300 默认 10。
- 报告日志截断显示：`ReportDetail.logs_total/logs_truncated`。

## 5. Protocol Registry 单一来源

- `agent/executor/protocol_manifest.yaml` 为动作/断言元数据**唯一可编辑来源**；
  `agent/scripts/generate_protocol.py` 生成只读产物（均带 DO NOT EDIT 头）：
  - `backend/app/protocol/action_registry.json`（`protocol_version` 供 Worker 下发）
  - `backend/app/schemas/generated_case_params.py`（后端校验模型）
  - `frontend/src/api/generated/registry.ts`（前端元数据）
- `--check` 进 CI；Agent 启动断言 decorator 注册集合与 manifest 完全一致（多/少都拒绝启动）。

## 6. 权限可见范围

- `backend/app/services/access_scope.py: visible_project_ids(user_id)`：
  owner / ProjectMember（EXISTS 防重复）/ visibility=public，排除软删除项目；
  reports、executions 未指定 project_id 时统一按其过滤；platform admin 不自动全量可见。
- 项目列表 `scope=all` 与 dashboard（“我的项目”，仅 owner/member）保持原有语义，命名区分可见资源/我的项目。
