> 版本：V2.0

## 1. 设计目标

新版采用“全局工作台 → 项目空间 → 设备选机 → 执行中心 → 报告分析”的主链路，将当前以 CRUD 菜单和表格为主的页面重组为任务导向的测试管理平台。

- 降低从测试资产维护到运行、监控和分析结果的操作成本。
- 让执行状态、设备状态和异常信息在关键页面中始终可见。
- 延续现有靛蓝品牌，统一颜色、间距、字号、圆角、阴影、状态和图表规范。
- 保留 Vue 3、TypeScript、Element Plus、Pinia、Vue Router 和 Vite 5。
- 重点支持 1280～1920px，并保证 1024px 宽度下可以完整操作。
- 本期不实现移动端、深色主题、通知中心、收藏和保存筛选。

交互参考 BrowserStack Test Management 的运行中心、筛选与仪表盘逻辑，以及 Sauce Labs 的设备检索、忙碌状态和选机流程；仅借鉴操作逻辑，不复制视觉设计。

## 2. 信息架构与导航

### 2.1 全局导航

登录后默认进入 `/dashboard`，全局侧边栏固定提供：

1. 工作台
2. 项目
3. 执行中心
4. 设备中心
5. 报告

根路由 `/` 重定向到 `/dashboard`。现有 `/projects`、`/executions`、`/devices`、`/reports` 等路径继续保留。

### 2.2 项目空间

进入项目后显示项目名称、当前用户角色和项目级导航：

1. 项目概览
2. 测试用例
3. 测试套件
4. 元素库
5. 变量
6. 项目设置

新增路由：

- `/projects/:projectId/overview`
- `/projects/:projectId/settings`
- `/executions/:executionId`

进入项目时默认打开项目概览，不再直接进入用例列表。

### 2.3 应用框架

- 1280px 及以上使用约 232px 的完整侧边栏。
- 1024～1279px 时折叠为图标栏，并通过 Tooltip 展示名称。
- 顶部栏高度约 56px，包含面包屑、项目上下文、刷新状态和用户菜单。
- 主内容区域使用流式宽度与统一间距。
- 移除没有后端能力的静态“通知”和“忘记密码”等入口。
- 用户身份读取 `is_admin`；项目权限读取接口返回的 `role`，禁止根据用户名推断权限。

- 页面标题、筛选栏、状态标签、统计卡片、空状态、错误状态和分页封装为公共组件。

## 4. 页面与交互设计

### 4.1 登录页

- 大屏使用品牌说明与登录卡片双栏结构，1024px 下压缩品牌区域。
- 只保留用户名、密码、记住登录和登录按钮。
- 登录成功进入工作台；存在原目标路由时返回目标路由。

### 4.2 工作台

顶部提供 7 天、30 天、90 天范围切换和刷新按钮，展示：

- 活跃执行数量。
- 周期内执行总数及成功率。
- 空闲设备数与设备总数。
- 可访问项目数。
- 执行趋势折线图和状态分布图。
- 最近执行与失败、异常、设备离线等关注项。
- 新建项目、创建用例、运行套件和进入设备中心的快捷入口。

### 4.3 项目列表与项目概览

项目列表保留卡片布局，增加真实名称搜索、角色与可见性筛选。单击卡片进入项目概览，编辑和删除收入更多菜单。空列表显示新建项目引导。

项目概览显示基本信息、用户角色、用例/元素/套件数量、项目执行趋势、最近执行和失败执行，并提供新建用例、运行套件、管理元素和项目设置入口。

### 4.4 测试用例

用例列表：

- 使用模块、状态、关键字组合筛选。
- 展示名称、模块、状态、步骤数、断言数、更新时间和最近结果。
- 保留“运行”和“编辑”为主操作；克隆、删除收入更多菜单。
- 编辑返回后保持筛选、分页和滚动位置。

用例编辑器：

- 顶部显示面包屑、名称、状态、保存和运行操作。
- 基本信息使用紧凑布局，步骤、断言、变量形成清晰分区。
- 步骤和断言使用可折叠卡片，支持拖拽、复制、删除和插入。
- 类型变化后按 Agent Registry 元数据重建参数。
- 必填元素和参数使用内联校验，并定位到首个错误项。
- 保存操作栏固定在页面底部。
- 表单有未保存修改时，离开页面必须确认。

### 4.5 测试套件

- 左侧为可搜索套件列表，右侧为当前套件用例。
- 套件摘要显示用例数、最近执行状态和更新时间。
- 用例选择支持模块和名称过滤，并排除已经加入的用例。
- 排序后显示保存结果，失败时恢复原顺序。
- 支持勾选多个套件发起批量执行。

### 4.6 元素库

- 左侧按元素的 `page_name` 显示页面分组，右侧显示元素表格。
- 用例模块来自 `test_modules`，其新增、重命名和删除入口放在测试用例页，不与元素页面分组混用。
- 支持名称、平台、定位方式和页面筛选。
- 元素编辑保留当前列表上下文。
- 引用列表可以直接进入对应用例编辑页。

### 4.7 变量

- 使用“项目变量”和“全局变量”页签。
- 展示变量名、值、作用域、描述和更新时间。
- 权限不足时保持可读，但隐藏编辑和删除入口。
- 不引入当前数据模型不支持的密钥变量类型。

### 4.8 设备中心

设备中心分为“我的设备”“Agent 与绑定”“下载安装”三个区域。

我的设备：

- 显示名称、UDID/地址、Android 版本、USB/Wi-Fi、所属 Agent、在线状态、占用执行和默认标记。
- 支持设置或清除默认设备。
- 管理员保留强制释放能力。

Agent 与绑定：

- 显示 Agent ID、主机名、平台、版本、最后心跳和设备数。
- 普通用户只看到自己绑定的 Agent，并可撤销自己的绑定。
- 管理员可查看全部 Agent并执行注销等管理操作。

下载安装：

- 显示 Windows x64 安装包版本、大小、SHA-256 和下载按钮。
- 支持用户专属 Key 的生成、查看、复制和重置。
- 提供安装 Agent、录入 Key、连接 USB/Wi-Fi Android 设备的引导。

### 4.9 统一运行与设备选择

用例、套件、批量套件和重试统一执行以下流程：

1. 用户点击运行。
2. 前端查询默认设备。
3. 默认设备有权限、Agent 在线、设备空闲且未被锁定时直接创建执行。
4. 默认设备缺失、离线、忙碌或失权时弹出设备选择器。
5. 选择器只显示当前用户有权限且在线空闲的设备。
6. 默认设备置顶，并提供“设为默认设备”选项。
7. 没有设备时显示下载安装 Agent、绑定 Key 和连接设备的引导。
8. 并发抢占失败时保留表单，提示“设备刚被其他执行占用”，刷新列表且不自动换机。

主运行按钮直接使用默认设备，同时提供“选择设备运行”次级入口。超时和参数放入高级设置。

### 4.10 执行中心与执行详情

执行中心支持项目、状态、类型、设备、关键字和时间筛选。列表展示执行对象、项目、设备、状态、耗时、创建时间和创建人，活跃执行突出显示。

点击执行进入独立详情页，不再使用大尺寸抽屉。详情页包含：

- 执行状态、对象、项目、设备、时间和耗时。
- 用例、步骤和断言时间线。
- 实时日志、级别过滤和自动滚动开关。
- 停止、重试和查看报告操作。
- WebSocket 重连后的日志补拉和状态同步。

### 4.11 报告

报告列表支持项目、执行状态、类型、时间和关键字筛选，突出成功率、失败数、设备、项目和耗时。

报告详情显示执行摘要、状态分布、步骤、断言、期望值、实际值、错误信息和截图；默认优先展开失败或异常用例，保留 HTML 报告按需生成和下载。

### 4.12 项目设置与成员

基本设置：

- owner/admin 可以修改名称、描述和可见性。
- 删除项目仅 owner 可见，并放在危险操作区域。

成员管理：

- 按用户名搜索候选人，不要求输入数字 ID。
- owner 可以管理 admin/member/viewer。
- admin 只能管理 member/viewer，不能授予、修改或移除 admin。
- owner 作为固定成员展示，不允许修改或移除。
- 禁止重复添加、添加 owner 或重复加入。
- member/viewer 只能查看成员列表。

## 5. 后端接口调整

### 5.1 工作台聚合

新增：

```http
GET /api/dashboard/overview?range=7d|30d|90d&project_id=<optional>
```

返回：

- `stats`：项目数、周期执行数、活跃执行数、成功率、空闲设备数和设备总数。
- `status_counts`：全部执行状态数量。
- `trend`：按 UTC 日期聚合的 `total/passed/failed/error`。
- `recent_executions`：最多 10 条，包含项目名、设备名和执行对象名称。

统计规则：

- 活跃执行为 `queued/running/stopping`。
- 成功率为 `passed / (passed + failed + error)`。
- 没有有效终态时返回 `null`，前端显示 `—`。
- 指定 `project_id` 时校验项目权限。
- 普通用户只统计其有权访问的数据。

### 5.2 执行与报告查询

扩展 `GET /api/executions`：

- `project_id`
- `device_id`
- `keyword`
- `created_from`
- `created_to`

执行列表项增加 `project_name` 和 `device_name`。

扩展 `GET /api/reports`：

- `project_id`
- `created_from`
- `created_to`

`POST /api/executions/{execution_id}/retry` 必须接收统一设备选择流程解析出的 `device_id`，并重新校验用户权限、Agent 状态和设备锁。

### 5.3 项目成员接口

```http
GET    /api/projects/{project_id}/members
GET    /api/projects/{project_id}/member-candidates?keyword=...
POST   /api/projects/{project_id}/members
PATCH  /api/projects/{project_id}/members/{user_id}
DELETE /api/projects/{project_id}/members/{user_id}
```

统一成员结构包含：

- `membership_id`，owner 为 `null`。
- `user_id`。
- `username`。
- `role`。

候选人搜索至少输入两个字符，最多返回 20 条，并排除 owner 和已有成员。所有项目权限依赖必须正确解包 `(project, role)`。

本次接口调整不新增数据表或数据库迁移。

## 6. 权限矩阵

| 能力 | owner | admin | member | viewer |
| --- | --- | --- | --- | --- |
| 查看项目资产 | 是 | 是 | 是 | 是 |
| 编辑用例/元素/套件/变量 | 是 | 是 | 是 | 否 |
| 发起与重试执行 | 是 | 是 | 是 | 否 |
| 查看执行和报告 | 是 | 是 | 是 | 是 |
| 修改项目设置 | 是 | 是 | 否 | 否 |
| 删除项目 | 是 | 否 | 否 | 否 |
| 管理 admin | 是 | 否 | 否 | 否 |
| 管理 member/viewer | 是 | 是 | 否 | 否 |

前端权限控制仅用于改善体验，后端仍必须执行完整权限校验。

## 7. 实施阶段

### Step 1：文档与公共框架

- 同步权威架构文档中的路由、接口和权限矩阵。
- 建立设计令牌和公共组件。
- 重构应用壳、响应式侧栏、顶部栏和面包屑。

### Step 2：工作台与项目协作

- 实现工作台聚合接口和图表。
- 完成项目列表、项目概览和项目设置。
- 补齐成员搜索、添加、角色修改和移除。

### Step 3：设备与执行主链路

- 完成设备中心三个区域。
- 接入 Windows Agent 下载、Key、绑定和默认设备能力。
- 建立统一设备选择器和运行流程。
- 重构执行中心和独立执行详情页。

### Step 4：测试资产

- 重构用例列表和编辑器。
- 重构套件、元素库和变量页面。
- 统一筛选、分页、权限、空状态和错误状态。

### Step 5：报告与全站收口

- 重构报告列表和详情。
- 完成登录页、404 页面和边界状态。
- 删除旧执行抽屉、重复样式和失效入口。
- 完成多分辨率和全链路验收。

每个 Step 独立执行 Lint、测试和构建，并按项目规范单独提交。正在开发的 Windows Agent 改动必须保留，不得覆盖无关未提交内容。

## 8. 测试与验收

### 8.1 后端测试

- 工作台全局和项目级统计口径。
- 用户、项目成员和管理员的数据隔离。
- 执行与报告新增筛选。
- 成员搜索、添加、角色修改、移除和越权矩阵。
- 默认设备、离线设备、忙碌设备和失权设备。
- 两个用户并发抢占同一设备，仅一个成功。
- 重试重新校验设备权限和设备锁。

### 8.2 前端测试

使用 Vitest、Vue Test Utils 和 Node 18 兼容的 DOM 环境覆盖：

- 登录、导航和根路由跳转。
- 侧边栏折叠和项目上下文切换。
- 工作台时间范围和项目统计。
- 按角色显示或隐藏操作。
- 默认设备直接运行与设备选择弹窗。
- 设置默认设备和并发占用错误恢复。
- 执行实时更新、停止、重试和报告跳转。
- 用例编辑器拖拽、校验、参数重建和未保存提示。
- 项目成员权限限制。

### 8.3 浏览器与构建验收

- 检查 1024、1280、1440、1920px 宽度。
- 除表格内部滚动外，不得出现整页横向滚动。
- 所有页面具备加载、空数据、请求失败、无权限和禁用状态。
- 不得保留没有实际行为的按钮或链接。
- 执行 `npm test`、`npm run build`。
- 执行 Backend Ruff、完整 pytest 和 Alembic check。

### 8.4 完整业务场景

1. 登录后进入工作台，只看到自己有权访问的数据。
2. 进入项目概览，新建并编辑用例。
3. 默认设备空闲时直接执行；不可用或未设置时弹出选择器。
4. 两个用户抢同一设备时，仅一个执行获得锁。
5. 执行详情实时更新，断线重连后不丢失历史日志。
6. 执行完成后查看报告、失败步骤、断言、截图并下载 HTML。
7. owner/admin/member/viewer 的页面能力符合权限矩阵。
8. 普通用户只看到绑定 Agent 下的设备，管理员可查看全部。
9. Agent 下载、Key、绑定撤销和默认设备设置流程完整。
10. 1024px 以上屏幕均可完成全部核心操作。

## 9. 默认假设

- 延续当前靛蓝主色和浅色界面。
- 第一版 Agent 只支持 Windows x64 与 Android。
- 默认设备是用户级全局设置，不按项目区分。
- 不新增通知、收藏、保存筛选、可配置仪表盘和深色主题。
- 不修改既有数据库表结构。
- 整体方案一次性定稿，代码按阶段实施和验收。
