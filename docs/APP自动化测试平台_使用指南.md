# APP 自动化测试平台使用指南

## 1. 文档说明

本文档面向项目管理员、测试人员、设备管理员和执行维护人员，介绍 APP 自动化测试平台从项目创建、用例编写、套件编排、APP 档案配置、Agent/设备接入，到执行和查看报告的完整流程。

本文档以当前项目的前端页面、后端接口和架构设计为准。页面名称可能随版本调整，但核心对象和操作流程保持一致。

平台的核心对象关系如下：

```text
项目
├── 测试元素
├── 测试用例
│   ├── 前置操作
│   ├── 执行步骤
│   └── 后置操作
├── 测试套件
│   ├── 套件前置步骤
│   ├── 用例列表
│   └── 套件后置步骤
├── APP 档案
│   └── 发布版本
├── 项目变量
└── 执行记录 / 测试报告

Agent
└── 设备
```

平台的执行职责分为三部分：

- 前端负责配置资产、发起执行、展示实时进度和报告。
- FastAPI 后端负责鉴权、执行请求、WebSocket 网关以及执行明细落库。
- Worker 负责队列消费、设备锁定、执行汇总和报告统计。
- Agent 负责连接真实设备，并执行动作和断言。

## 2. 快速开始

### 2.1 使用前检查

正式使用前请确认以下条件已经具备：

1. 平台服务端已启动，数据库已完成迁移。
2. 至少有一个可登录的平台账号，并且该账号已加入目标项目。
3. 如果需要真实设备执行，至少有一个已连接并在线的 Agent，且 Agent 下有授权、在线、空闲的设备。
4. 如果使用 APP 档案执行，已经创建档案和有效的发布版本。
5. 用例中引用的测试元素、变量和动作参数已经配置完成。

### 2.2 本地开发环境启动

以下命令适用于当前项目的本地开发环境。PowerShell 5.1 不支持 `&&`，建议逐条执行。

启动后端：

```powershell
cd D:\sjs\app_auto_test\backend
$env:Path = "$env:USERPROFILE\.local\bin;" + $env:Path
.\start-backend.ps1 -Migrate -Seed
```

`-Seed` 会创建开发环境管理员账号 `admin / admin123`。生产环境不要继续使用默认密码，也不要在生产环境重复使用开发密钥。

启动前端：

```powershell
cd D:\sjs\app_auto_test\frontend
npm run dev
```

当前开发环境通常使用：

- 前端：`http://127.0.0.1:5173`
- 后端：`http://127.0.0.1:8001`

前端开发服务器会把 `/api` 和 `/ws` 请求代理到后端 8001 端口。实际部署时请使用部署人员提供的平台地址。

### 2.3 登录后的页面范围

平台分为全局页面和项目工作区两类：

- 全局页面：工作台、项目管理、全局元素库、全局执行中心、设备中心、全局报告中心。
- 项目工作区：项目概览、用例、套件、APP 档案、元素库、变量、执行中心、报告中心、项目设置。

在项目列表中点击“打开项目”后，左侧菜单会切换到该项目的工作区。

### 2.4 权限说明

| 角色 | 查看项目资产 | 编辑用例/套件/档案 | 执行测试 | 编辑项目信息 | 管理成员 | 删除项目 |
|---|---:|---:|---:|---:|---:|---:|
| Owner | 是 | 是 | 是 | 是 | 是 | 是 |
| Admin | 是 | 是 | 是 | 是 | 是 | 否 |
| Member | 是 | 是 | 是 | 否 | 否 | 否 |
| Viewer | 是 | 否 | 否 | 否 | 否 | 否 |

平台管理员可以管理全局资源和平台级配置，但仍应按项目权限进行日常协作。Viewer 可以查看资产、执行记录和报告，不能编辑资产或发起执行。

## 3. 项目管理

项目是用例、套件、APP 档案、变量、设备执行和报告的隔离边界。除全局元素库和全局变量外，大部分测试资产都属于某个项目。

### 3.1 创建项目

1. 进入左侧“项目管理”。
2. 点击“新建项目”。
3. 填写：
   - 项目名称：必填，建议使用产品或业务线名称。
   - 项目描述：填写测试范围、目标版本或维护人等信息。
   - 可见性：选择“私有”或“公开”。
4. 点击保存。

私有项目只对项目成员可见；公开项目可被符合平台权限规则的用户发现和进入，但仍建议通过成员角色控制编辑和执行权限。

### 3.2 查找和打开项目

项目管理页支持：

- “全部”：查看当前账号可见的全部项目。
- “我创建的”：只查看自己创建的项目。
- “公开”：筛选公开项目。
- 关键词搜索：按名称或描述查找。
- 角色筛选：按当前账号在项目中的角色筛选。
- 分页：项目较多时分页浏览。

点击项目卡片或“打开项目”进入项目工作区。建议进入项目后先查看“概览”和“项目设置”，确认成员、档案和执行条件。

### 3.3 编辑项目

Owner 和 Admin 可以在项目设置的“基本信息”中修改项目名称、描述和可见性。

修改项目名称后，项目内的用例、套件、档案和报告不会改变归属，但依赖项目名称的外部文档、截图或发布说明需要同步更新。

### 3.4 管理成员与权限

1. 进入“项目设置 → 成员与权限”。
2. 搜索需要加入的用户。
3. 添加成员并选择角色：Viewer、Member 或 Admin。
4. 根据需要调整已有成员角色或移除成员。

建议按最小权限分配：

- 只查看结果的人员使用 Viewer。
- 编写和维护测试资产的人员使用 Member。
- 需要管理成员和项目基本信息的人员使用 Admin。
- 项目负责人使用 Owner。

### 3.5 删除项目

只有 Owner 可以删除项目。删除入口位于“项目设置 → 危险操作”。系统要求输入项目名称进行确认。

删除项目会连带删除项目下的测试资产和关联数据。执行前应确认是否需要保留报告、日志或截图，并先导出或归档重要资料。

## 4. 用例管理

用例描述一次可重复执行的测试流程。每个用例由基本信息、前置操作、执行步骤、后置操作和用例变量组成。

### 4.1 编写用例前的准备

建议按以下顺序准备资产：

1. 创建项目并配置成员。
2. 在“元素库”中创建页面控件元素，或确认可以使用坐标、智能定位等方式操作。
3. 在“变量”中创建项目变量或全局变量。
4. 在“用例”中创建模块和用例。
5. 在用例编辑器中配置动作和断言。

元素库不是编写所有用例的强制前置条件，但对于点击、输入、读取文本等控件操作，使用元素引用比直接写定位器更容易维护。

删除元素时，系统会检查仍未删除的用例（包括断言和动作参数）、套件前后置步骤以及 APP 档案中的元素/节点覆盖。存在这些引用时删除会提示“元素仍被可执行资产引用”，元素和项目资产版本都不会改变；历史执行快照、报告以及已删除的用例、套件或档案不会阻止删除。

### 4.2 用例列表和模块

进入项目工作区的“用例”页面后，可以看到：

- “全部用例”：查看项目内全部用例。
- “未分组”：查看没有归属模块的用例。
- 模块树：按业务模块组织用例。
- 关键词筛选：按用例名称查找。
- 状态筛选：按草稿、启用、禁用筛选。

建议按照业务功能、页面或测试层级建立模块，例如：登录、首页、订单、个人中心。模块调整只改变组织方式，不会改变用例本身。

### 4.3 创建和编辑用例

点击“新建用例”或在用例列表中编辑，填写：

- 用例名称：应体现业务动作和预期结果，例如“登录成功后进入首页”。
- 所属模块：选择合适模块，也可以暂时放入未分组。
- 状态：
  - 草稿：仍在编写或验证中。
  - 启用：允许被执行。
  - 禁用：保留用例但不允许通过正常执行入口运行。
- 描述：记录测试目的、前置环境、版本要求或注意事项。

保存时会校验用例名称、步骤和步骤参数。任何步骤校验失败都会阻止保存，需按页面提示修正。

### 4.4 配置前置、执行和后置操作

用例编辑器包含三个区域：

#### 前置操作

用于准备用例运行环境，例如启动 APP、登录、切换页面、设置测试数据等。

前置操作是否执行由“启用前置操作”开关控制。关闭后，这些步骤会保留在用例中，但本次执行不会运行。

#### 执行步骤

这是用例的主要业务流程，例如点击按钮、输入文本、滑动页面和校验结果。主执行步骤始终属于用例主体。

#### 后置操作

用于清理环境或恢复状态，例如退出登录、关闭 APP、删除测试数据等。

后置操作是否执行由“启用后置操作”开关控制。后置操作位于用例末尾，即使主流程失败，系统仍会尝试执行已启用的后置操作。

### 4.5 添加动作步骤

在对应区域点击“添加步骤”，选择动作。当前支持的动作包括：

| 动作 | 常见用途 |
|---|---|
| 启动 APP | 启动目标应用 |
| 关闭 APP | 关闭目标应用 |
| 点击 | 点击元素 |
| 输入 | 向输入框输入文本 |
| 清空 | 清空输入框 |
| 滑动 | 执行方向或区域滑动 |
| 滑动查找 | 滑动查找目标元素 |
| 元素内滑动 | 在指定元素区域内滑动 |
| 滑动区域查找并点击文本 | 滑动查找文本并点击 |
| 滚动 | 执行页面滚动 |
| 返回 | 返回上一级页面 |
| 等待 | 按时间等待 |
| 截图 | 保存当前画面 |
| 获取文本 | 读取元素文本 |
| 获取属性 | 读取元素属性 |
| 坐标点击 | 点击指定屏幕坐标 |

选择动作后，根据页面提示填写元素、参数和描述。需要元素的动作应选择元素库中的元素；坐标点击、部分滑动动作可直接填写坐标或区域参数。

参数中可以使用变量占位符，例如：

```text
${username}
${password}
${order_id}
```

变量在执行时解析。未定义变量会导致执行失败，因此保存用例后应至少在一次真实或联调执行中验证变量配置。

### 4.6 配置断言

断言添加在动作步骤下方，动作成功后立即执行。当前支持：

- 元素存在
- 文本等于
- 文本包含
- 文本不包含
- 属性等于
- 属性包含
- 值等于
- 正则匹配

一个动作可以配置多个断言，断言按列表顺序执行。例如：

```text
点击“登录”按钮
└── 断言：元素存在“首页标题”
└── 断言：文本包含“欢迎回来”
```

动作失败时，该动作下的断言不会执行。对于偶发性、非关键步骤，可以开启“失败后继续”；对于关键步骤建议关闭，避免后续步骤在错误页面上继续运行并产生误导性结果。

### 4.7 用例变量

在用例编辑器的变量区域可以添加键、值和说明。例如：

| 键 | 值 | 用途 |
|---|---|---|
| username | test_user | 登录账号 |
| password | ****** | 登录密码 |
| keyword | 自动化 | 搜索关键词 |

变量优先级固定为：

```text
执行参数 > 套件变量 > 用例变量 > 项目变量 > 全局变量
```

同名变量使用优先级更高的一层。变量名应使用字母、数字和下划线，避免在不同层级重复定义同名变量造成排查困难。

### 4.8 排序、复制和删除

- 拖动步骤可以调整执行顺序。
- 断言可以在同一步骤内调整顺序。
- 可以复制用例作为相似场景的模板，再修改名称和差异步骤。
- 删除用例是软删除，不会因历史执行或套件引用而被阻止；历史执行和报告仍从执行快照读取。
- 支持批量删除；批量操作前应先筛选并核对选中范围。

禁用用例不会被正常执行入口选中。套件中已有的禁用用例仍应在套件配置中检查，避免执行时产生不适用内容。

### 4.9 推荐的用例编写示例

以“登录成功”为例：

1. 基本信息：名称填写“登录成功后进入首页”，状态设为启用。
2. 前置操作：启动 APP，等待首页加载。
3. 执行步骤：
   - 点击用户名输入框。
   - 输入 `${username}`。
   - 点击密码输入框。
   - 输入 `${password}`。
   - 点击登录按钮。
   - 断言首页标题元素存在。
   - 断言欢迎文本包含“欢迎”。
4. 后置操作：关闭 APP 或退出登录。
5. 保存后先单独执行一次，再加入回归套件。

## 5. 套件管理

套件用于把多个用例编排成一组可重复执行的测试集合，也是批量执行和结果汇总的主要单位。

### 5.1 创建套件

1. 进入项目工作区的“套件”。
2. 点击“新建套件”。
3. 填写套件名称和描述。
4. 保存后进入套件配置页。

建议一个套件对应一个明确目标，例如“登录回归”“支付主流程”“版本冒烟”“Android 兼容性回归”。

### 5.2 添加和编排用例

在套件配置页点击“添加用例”，从项目用例中选择要纳入套件的用例。

支持的操作包括：

- 添加用例。
- 移除用例。
- 拖动调整用例顺序。
- 搜索用例。
- 查看套件内用例数量。

用例的添加、移除和排序会自动保存；建议完成编排后刷新或重新进入套件确认顺序。

套件通常不复制用例内容，而是引用项目中的用例资产。因此修改用例后，引用该用例的套件会使用最新用例配置。需要固定版本时，应结合 APP 档案发布版本和执行时的资产快照进行管理。

### 5.3 配置套件级前置和后置步骤

套件级步骤与用例级前置、后置步骤不同：

- 套件前置步骤：在整个套件开始时执行一次。
- 用例前置步骤：每个用例开始前执行。
- 用例后置步骤：每个用例结束后执行。
- 套件后置步骤：在整个套件结束时执行一次。

适合放在套件级的内容包括：统一登录、准备公共数据、切换测试环境、恢复公共数据和关闭测试资源。

配置套件级步骤后，需要点击页面底部的“保存套件配置”完成手动保存。不要只配置后直接离开页面。

### 5.4 套件变量

套件变量适合保存本套件中多个用例共享的值，例如环境地址、公共账号、业务租户或测试订单号。

套件变量的优先级高于用例变量、项目变量和全局变量，但低于本次执行时显式传入的执行参数：

```text
执行参数 > 套件变量 > 用例变量 > 项目变量 > 全局变量
```

修改套件变量会立即保存。对于密码、Token 等敏感值，建议使用安全的环境配置或短期执行参数，避免在套件描述、日志和报告中直接写入明文。

### 5.5 删除套件

删除套件前，确认是否有持续集成任务、人工流程或团队文档依赖它。删除套件会移除套件编排关系，不等同于删除套件内被引用的用例。

### 5.6 运行套件

在套件列表或套件详情页点击“运行套件”，进入设备和执行参数选择页面。正式运行前请检查：

- 套件内用例是否均为启用状态。
- 套件级前置和后置步骤是否已保存。
- 套件变量是否完整。
- APP 档案和发布版本是否匹配目标设备。
- Agent 是否在线并有可用设备。

## 6. APP 档案管理

APP 档案用于描述同一套公共测试资产在不同 APP、版本、设备或环境上的差异。公共用例、套件和元素不需要为每个 APP 重复复制，档案只保存差异配置。

### 6.1 什么时候使用 APP 档案

以下场景适合使用 APP 档案：

- 同一套用例需要在多个 APP 包名或产品版本上执行。
- 不同 APP 的元素定位器不同，但业务流程相同。
- 某些套件、用例、步骤或断言在指定 APP 上不适用。
- 某个 APP 需要覆盖项目变量或动作参数。
- 需要对一组差异配置做版本化和发布管理。

如果所有环境完全一致，可以先直接使用项目公共资产；当差异出现后再创建档案。

### 6.2 创建档案

1. 进入项目工作区的“APP 档案”。
2. 点击“新建档案”。
3. 填写档案名称和描述。
4. 保存后进入档案工作区。

档案页面会显示当前修订号、发布数量以及跳过和覆盖统计。档案配置修改后，修订号会变化；正在执行或准备发布前应确认修订号与预期一致。

### 6.3 创建和管理发布版本

档案工作区的“发布管理”用于创建可执行的发布版本。创建发布时填写：

- 版本号，例如 `2026.08.1`。
- 构建号或对应 APP 构建信息。
- 发布说明。

建议版本号和实际 APP 包版本保持一致，并在发布说明中记录包名、构建渠道、兼容设备和主要差异。

执行 APP 档案时需要选择有效的发布版本。修改档案后，原有发布版本不会自动代表最新修订；需要按团队流程创建新发布或确认当前发布仍适用。

### 6.4 查看档案工作区

档案工作区按以下层级展示公共测试资产：

```text
套件
├── 套件前置 / 套件后置
├── 用例
│   ├── 用例前置
│   ├── 执行步骤
│   └── 用例后置
└── 步骤断言
```

页面支持搜索套件和查看节点的有效状态。可以筛选：

- 全部。
- 已启用。
- 已跳过。
- 已覆盖。

### 6.5 配置跳过规则

当某些节点在当前 APP 或设备上不适用时，可以对套件、用例、步骤或断言设置跳过。跳过时选择原因：

- 不支持。
- 尚未适配。
- 已废弃。
- 环境限制。
- 其他。

选择“其他”时必须填写说明。跳过规则应描述具体原因和适用范围，例如“仅 iOS 支持，Android 暂不执行”，不要使用没有上下文的“暂时跳过”。

跳过规则可以恢复。恢复后节点重新跟随公共资产的执行状态。

### 6.6 配置元素覆盖

当公共元素在某个 APP 上定位方式不同，可以在档案覆盖抽屉中为该元素设置覆盖值。支持普通定位方式，例如：

- `id`
- `resource_id`
- `xpath`
- `accessibility_id`
- `class_name`
- `uiautomator`
- `predicate`
- `coordinate`
- `custom`

Android 场景还支持智能定位器。覆盖配置只保存与公共元素的差异；点击恢复后，档案会重新使用公共元素配置。

### 6.7 配置变量覆盖

档案可以覆盖项目变量或全局变量的值，用于不同 APP、环境或租户。例如同一个 `api_host` 在测试环境和预发布环境中不同。

变量覆盖同样只保存差异。删除覆盖或恢复后，系统会重新继承公共变量值。实际执行时，档案变量仍需与执行参数、套件变量和用例变量共同遵守优先级规则。

### 6.8 配置节点参数覆盖

对于某个档案需要调整动作或断言参数的情况，可以使用节点覆盖。节点覆盖只允许覆盖受支持的节点字段，不应修改节点身份、层级关系或断言归属。

覆盖后建议立即查看档案差异列表，确认差异只落在预期节点。

### 6.9 查看差异和执行预览

点击“差异”可以集中检查当前档案相对于公共资产的：

- 元素覆盖。
- 变量覆盖。
- 节点参数覆盖。
- 跳过规则。

点击“执行预览”可以看到本次档案执行将包含的来源用例、实际可执行用例和步骤、不适用内容以及覆盖数量。

预览发现以下情况时不要直接执行：

- 可执行用例数量为 0。
- 关键用例被标记为 N/A。
- 大量元素仍使用公共定位器但当前 APP 已发生变化。
- 当前发布版本与 APP 实际安装版本不一致。

### 6.10 档案执行要求

使用档案执行通常需要：

1. 选择档案。
2. 选择有效发布版本。
3. 选择在线空闲设备。
4. 预览通过且没有阻断性问题。
5. 确认档案修订号和测试资产修订号仍是预期版本。

如果在打开预览后又修改了公共用例、套件或档案，系统可能提示配置版本冲突。此时应重新预览，确认变更后再发起执行。

## 7. Agent 客户端下载安装与连接管理

Agent 是部署在测试机上的客户端，负责把本机 Android/iOS 设备接入平台并执行动作。Worker 不直接控制设备，所有设备操作均通过 FastAPI 转发给 Agent。

### 7.1 Agent 运行条件

Windows Agent 当前面向 Windows x64。使用真实 Android 设备时，测试机还需要：

- 安装并可用的 ADB/platform-tools。
- 手机开启开发者选项和 USB 调试。
- Windows 已安装对应 USB 驱动。
- 如果使用 Appium，Appium 服务及驱动已经准备好。

首次联调可以使用 Agent 的 mock 驱动验证平台链路，但 mock 设备不能代表真实设备的页面定位和动作结果。

### 7.2 获取客户端安装包

管理员在“设备中心”查看 Windows Agent 发布信息和下载入口。安装包发布目录由后端配置的 Agent release 目录提供，目录中通常包含版本目录、安装包、校验值和 `latest.json`。

如果设备中心没有可下载版本，说明当前服务端尚未发布 Agent 安装包，需要由维护人员先完成打包发布。源码仓库中的打包流程示例为：

```powershell
cd D:\sjs\app_auto_test\agent
powershell -ExecutionPolicy Bypass -File packaging\publish.ps1 -Version 2.2.0 -ReleaseDir ..\backend\data\agent-releases
```

实际版本号和发布目录以部署环境配置为准。下载后建议核对页面或发布目录提供的 SHA256，确认安装包未损坏或被替换。

### 7.3 安装客户端

1. 在测试机下载 Windows Agent 安装包。
2. 运行安装程序，按向导完成安装。
3. 安装后从开始菜单或桌面启动 Agent。
4. Agent 默认支持托盘运行，并可配置为随 Windows 启动。
5. 在 Agent 设置中确认服务端地址。WebSocket 地址格式通常为：

```text
ws://127.0.0.1:8001/ws/agent
```

生产环境应替换为实际平台地址，并按部署方式使用 `ws://` 或 `wss://`。

### 7.4 获取个人 User Key

平台使用个人 User Key 将客户端绑定到用户。获取流程：

1. 登录平台。
2. 进入“设备中心”。
3. 在“个人 Key”区域生成或复制 User Key。
4. 将 User Key 粘贴到 Agent 客户端的绑定界面。
5. 点击绑定或连接。

User Key 等同于连接凭证，不要提交到代码仓库、截图、群聊或报告中。怀疑泄露时应立即在设备中心重置或撤销，并重新绑定客户端。

一个 Agent 可以绑定多个用户，但普通用户只能看到和使用自己有权限的 Agent 及其设备；管理员可按管理权限查看更大范围的资源。

### 7.5 源码方式启动 Agent

仅在开发、调试或没有安装包时使用源码启动：

```powershell
cd D:\sjs\app_auto_test\agent
$env:Path = "$env:USERPROFILE\.local\bin;" + $env:Path
uv run python main.py --config config.yaml --self-check
uv run python main.py --config config.yaml --bind YOUR_USER_KEY
```

也可以使用项目脚本：

```powershell
.\start-agent.ps1 -Config .\config.yaml
```

`config.yaml` 可参考 `config.yaml.example` 创建。配置中不要写入用户密码；绑定身份由安装标识和 User Key 管理。

### 7.6 连接成功的判断方式

绑定后在“设备中心”检查：

- Agent 是否出现在“已绑定 Agent”区域。
- Agent 是否显示在线。
- 最后心跳时间是否持续刷新。
- “我的设备”中是否出现设备。
- 设备是否为授权且空闲状态。

设备中心默认定时刷新。必要时可以手动刷新页面。

### 7.7 Agent 和设备状态

常见状态及处理方式：

| 状态 | 含义 | 处理方式 |
|---|---|---|
| 在线 / online | Agent 已连接服务端 | 可继续检查设备状态 |
| 离线 / offline | Agent 心跳中断或连接断开 | 检查客户端、服务端地址、防火墙和网络 |
| unauthorized | 设备未授权 | 在设备上确认 USB 调试授权并重新连接 |
| device | 设备已连接，可被平台使用 | 检查是否空闲 |
| offline（设备） | 设备连接中断 | 检查 USB、ADB、驱动或设备网络 |
| busy | 设备已被其他执行占用 | 等待执行结束或查看占用执行记录 |

只有在线、已授权、空闲的设备适合发起新执行。执行开始后平台会锁定设备，避免多个执行同时控制同一台设备。

### 7.8 设备中心常用操作

设备中心主要包含：

- Windows Agent 发布和下载。
- 个人 User Key 管理。
- 已绑定 Agent 列表。
- 我的设备列表。
- Agent/设备实时状态。

管理员还可以处理不再使用的 Agent、撤销绑定或清理失效连接。删除或撤销前应确认没有正在运行的执行任务。

## 8. 用例执行

### 8.1 执行入口

常用执行入口包括：

- 用例列表中的“运行”。
- 套件列表或套件详情中的“运行套件”。
- APP 档案工作区中的“运行当前 APP 全部套件”或单套件/用例运行。
- 全局或项目执行中心查看已提交任务。

用例适合单场景调试，套件适合回归和批量验证，APP 档案适合带版本差异和适配规则的执行。

### 8.2 选择设备和执行参数

点击运行后会打开设备选择窗口。根据执行类型配置：

1. APP 档案和发布版本：使用档案执行时必填；普通公共资产执行按页面提示选择。
2. 设备：只能选择在线、已授权、空闲的设备。
3. 是否设为默认设备：设为默认后，后续运行可以减少重复选择。
4. 超时时间：默认 1800 秒，可配置范围为 60 至 86400 秒（24 小时）。
5. 是否执行用例前置步骤。
6. 是否执行用例后置步骤。
7. 执行参数：输入本次执行要覆盖的变量值。
8. 单用例场景下是否附着当前 APP：适用于设备上 APP 已经处于正确页面、不希望重新启动 APP 的调试场景。

套件级前置和后置步骤由套件配置决定，不应与单个用例的前置、后置开关混淆。

### 8.3 执行预检查

设备选择窗口会显示预检查摘要，包括来源用例、实际可执行用例和步骤、N/A 内容以及覆盖信息。提交前重点检查：

- 是否选择了正确设备。
- 是否选择了正确 APP 发布版本。
- 是否有用例被排除或标记为 N/A。
- 是否有未解析变量。
- 是否有元素覆盖或节点覆盖未生效。
- 是否存在配置版本冲突。

预检查通过后点击“开始执行”。指定设备的预检查会生成一个仅短时间有效的一次性预检令牌，开始执行时由服务端复用这次解析结果；令牌不会包含在日志中，也不能跨用户、设备、档案版本或目标复用。平台会创建执行记录并将任务放入队列。

在 APP 档案工作区点击“运行当前 APP 全部套件”时，平台会把“全部套件”作为服务端
目标范围提交，不需要浏览器分页收集套件 ID；服务端按当前项目、档案、发布版本和
双 revision 确定目标并应用跳过规则。普通批量执行仍按用户明确选择的套件提交。

### 8.4 执行状态

执行状态全部使用小写值：

| 状态 | 含义 |
|---|---|
| `queued` | 已进入队列，等待 Worker 调度 |
| `running` | 正在执行 |
| `stopping` | 已收到停止请求，正在收尾 |
| `passed` | 执行通过 |
| `failed` | 业务断言或步骤失败 |
| `error` | 系统、通信或执行异常 |
| `stopped` | 用户主动停止 |
| `cancelled` | 任务被取消，未正常完成 |

执行列表可按状态、执行类型和关键词筛选。执行类型包括用例、套件和批量执行。

### 8.5 查看执行详情

打开执行详情后，可以查看嵌套的：

```text
套件 → 用例 → 步骤 → 断言
```

详情页会显示：

- 当前状态和整体进度。
- 每个步骤和断言的结果。
- 执行日志。
- Agent/设备反馈。
- 实时 WebSocket 更新。
- 断线后的 REST 数据重新同步结果。

如果执行仍在运行，可以点击“停止”。状态通常先变为 `stopping`，待 Worker 和 Agent 完成收尾后进入 `stopped`。执行超过超时时间时也先进入 `stopping`，由服务端经内部通道向 Agent 发送 `stop_test`；发送失败会按退避周期重试，Agent 确认后以 `error` 结束并显示“执行超时（>Ns）”。若 Agent 无法确认，持久化的停止宽限期到期后由 Worker 兜底汇总并释放设备。宽限期内不会提前把未执行用例标记为 skipped，也不会释放设备锁。

### 8.6 重试执行

执行详情和执行列表支持重试。只有 `passed`、`failed`、`error`、`stopped`、`cancelled` 终态可以重试；
`queued`、`running`、`stopping` 会返回不可重试提示。重试会创建新的执行记录，原执行记录保留用于审计和对比。

重试沿用原执行已经物化的套件、用例、步骤、断言、节点和不适用项快照，并使用新的设备入队；
不会重新读取当前用例、套件、元素、变量、APP 档案或发布版本。原执行缺少完整快照时，系统会提示
“执行快照未就绪”，不会留下半棵重试执行树。

重试前建议确认：

- 设备已经恢复空闲。
- Agent 已重新在线。
- APP 已回到可执行状态。
- 失败是否由数据、元素定位或环境问题造成。

页面会展示原执行保存的档案、发布版本和 revisions；这些信息用于说明快照来源，不要求当前档案仍存在，
也不会因为当前资产后来修改而阻止重试。

## 9. 测试报告

### 9.1 打开报告中心

报告中心分为全局报告中心和项目报告中心：

- 全局报告中心：查看当前账号有权限访问的执行报告。
- 项目报告中心：查看当前项目的报告，并可按 APP 档案和发布版本筛选。

支持按报告状态、执行 ID、执行类型、项目、档案和发布版本筛选。

### 9.2 报告列表字段

报告列表通常包含：

- 报告 ID。
- 执行 ID。
- 执行类型和名称。
- 所属项目。
- APP 档案和发布版本。
- 执行状态。
- 通过数、总数和成功率。
- N/A 数量。
- 执行耗时。
- 开始和结束时间。

点击报告记录进入报告详情。

### 9.3 报告详情内容

报告详情包含：

1. 执行状态、执行入口和重试入口。
2. 设备、超时、开始时间、结束时间和耗时。
3. APP 档案、发布版本、档案修订号和测试资产修订号。
4. 本次执行参数。
5. 用例、套件和步骤三层统计。
6. 不适用内容及跳过原因。
7. 套件、用例、步骤和断言的嵌套明细。
8. 执行日志和失败过滤。
9. 截图或其他执行证据（如果动作产生了相应数据）。

报告保留执行时的配置快照，因此后续修改公共用例、套件或档案不会改变历史报告的执行依据。

### 9.4 成功率和 N/A 的计算

报告同时提供用例级、套件级和步骤级统计。被跳过或不适用的内容单独统计为 N/A，不计入成功率分母。

例如：总共 10 个用例，其中 2 个因平台不支持被标记为 N/A，剩余 8 个中 7 个通过，则成功率按 8 个可执行用例计算，而不是按 10 个计算。

查看报告时应同时关注：

- 通过率。
- N/A 数量及原因。
- 失败步骤和断言。
- 是否是同一设备或同一元素持续失败。
- 失败是否发生在套件前置、用例主体或后置清理阶段。

### 9.5 下载 HTML 报告

报告详情中的“下载 HTML 报告”会按需生成 HTML，而不是在每个执行结束时预先生成。首次下载可能需要等待报告渲染。

HTML 报告适合发送给没有平台账号的人员或归档到版本测试资料中。报告中的截图、日志和执行数据应按公司安全要求处理。

## 10. 常见问题排查

### 10.1 运行时没有可用设备

依次检查：

1. Agent 客户端是否正在运行。
2. Agent 服务端地址是否正确。
3. User Key 是否有效且绑定成功。
4. 设备是否显示为 `unauthorized`、`offline` 或 `busy`。
5. Android 是否确认 USB 调试授权。
6. 是否有其他执行占用设备。

只有在线、授权、空闲设备会出现在可执行设备列表中。

### 10.2 Agent 在线但设备是 unauthorized

在设备上解锁屏幕，重新插拔 USB，确认“允许 USB 调试”授权；然后检查 ADB 是否能发现设备。若设备曾更换电脑或清除过调试授权，需要重新确认 RSA 授权。

### 10.3 Agent 一直离线

检查 Agent 日志和以下配置：

- WebSocket 服务端地址。
- 服务端端口和反向代理配置。
- Windows 防火墙或公司网络策略。
- User Key 是否被撤销。
- 客户端是否使用了过期版本。

如果平台服务端重启，Agent 通常会自动重连；仍无心跳时可重启 Agent 客户端。

### 10.4 提示 APP 档案或发布版本不可用

确认：

- 已创建 APP 档案。
- 已创建有效发布版本。
- 运行选择的档案和发布版本属于同一项目。
- 档案预览没有阻断性问题。
- 当前档案修订号没有被新修改覆盖。

### 10.5 提示配置版本冲突

这通常表示预览后公共用例、套件、元素或档案发生了变化。重新打开执行弹窗，重新预览并确认最新差异后再提交，不要直接重复点击提交。

### 10.6 提示变量未定义

检查变量名拼写和作用域：

```text
执行参数 > 套件变量 > 用例变量 > 项目变量 > 全局变量
```

确认 `${variable_name}` 中的名称与变量键完全一致。变量名大小写、下划线和空格都可能造成不匹配。

### 10.7 元素找不到或定位不唯一

先在元素库确认定位器是否仍适用于当前 APP 和设备，再检查：

- 当前选择的 APP 发布版本是否正确。
- 当前档案是否配置了元素覆盖。
- 元素是否需要使用 `resource_id`、`accessibility_id` 或 Android 智能定位器。
- 页面是否需要等待、滚动或先执行前置操作。
- 元素是否处于弹窗、WebView 或权限对话框中。

不要为了让一次执行通过而盲目延长超时；应优先修复定位器和页面准备步骤。

### 10.8 执行停在 queued

检查 Worker 是否运行、设备是否被其他任务占用、Agent 是否在线以及队列中是否有大量任务。当前默认 Worker 模式为嵌入 FastAPI 运行；如果部署改为 external 模式，需要确认独立 Worker 进程已启动。

### 10.9 执行状态为 error

`error` 通常代表系统、通信或设备层异常，不等同于业务断言失败。查看执行详情日志，重点区分：

- Agent 与服务端断连。
- 设备在执行中掉线。
- Appium/ADB 异常。
- Worker 无法获取设备锁。
- 参数、变量或配置解析失败。

修复环境后再重试，并保留原始错误报告。

### 10.10 报告中出现大量 N/A

检查 APP 档案的跳过规则和预览结果。N/A 不是失败，但大量 N/A 可能意味着：

- 选择了错误的 APP 档案或发布版本。
- 当前设备不在适配范围内。
- 档案跳过规则配置过宽。
- 公共用例尚未完成当前 APP 的适配。

## 11. 推荐的标准工作流

首次建立一个新项目时，建议按以下顺序执行：

1. 创建项目并设置可见性。
2. 在成员与权限中加入测试开发、执行和查看人员。
3. 接入 Agent，确认至少有一台真实设备在线、授权、空闲。
4. 创建全局或项目变量。
5. 创建元素库中的公共元素。
6. 创建用例模块和基础用例。
7. 单独运行用例，修复动作、断言、变量和定位问题。
8. 创建套件，添加用例并调整顺序。
9. 添加套件级准备和清理步骤，点击保存套件配置。
10. 如果存在 APP 差异，创建 APP 档案。
11. 配置跳过规则、元素覆盖、变量覆盖和节点参数覆盖。
12. 创建并确认 APP 发布版本。
13. 用执行预览检查实际可执行内容。
14. 先运行一个小套件，再运行完整回归套件。
15. 在报告中确认通过率、N/A、失败步骤、断言和日志。
16. 对修复后的问题重新执行，并保留前后两份报告用于对比。

## 12. 维护建议

- 用例名称、套件名称和 APP 发布版本使用统一命名规则。
- 公共元素尽量集中维护，档案只保存差异。
- 关键流程必须配置断言，不要只依赖动作成功。
- 每个套件都应有明确的前置准备和后置清理策略。
- 设备执行前确保电量、网络、系统时间和 APP 版本符合测试要求。
- User Key、密码、Token 和测试数据不要写入公开描述或提交到仓库。
- 修改公共资产后重新查看受影响的 APP 档案和套件预览。
- 定期清理失效 Agent、离线设备和长期无效的档案覆盖。
- 重要版本发布前保存报告 HTML，并记录 Agent、设备和 APP 构建信息。
